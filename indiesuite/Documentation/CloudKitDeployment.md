# CloudKit deployment evidence

Production schemas for the five new apps were deployed through Apple’s CloudKit Console on 18 November 2026. Each additive deployment was confirmed by the console, followed by a production export readback. These exports contain schema definitions only; no records, credentials or account identifiers are included.

The definitions were generated by Apple’s `NSPersistentCloudKitContainer.initializeCloudKitSchema` API from the actual shared SwiftData model classes. Each app passed an authenticated schema dry run and real development initialization, using a Mac Catalyst helper signed with that app’s own bundle identifier and private CloudKit container. Production deployment adds the application types, indexes and SDK-generated roles; development records are not copied.

The applications use the private CloudKit database. The SDK-generated role declarations in these schema files do not make a user’s private-database records public. No CloudKit web/API keys are embedded in the applications.

The container factory now uses CloudKit account status rather than the iCloud Drive identity token. It retains one durable cache URL when account availability changes and adopts an existing legacy local store in place. The [20 offline storage checks](CloudStorageResults.md) cover schema constraints, real SQLite reopen, relationships, receipt data, cascades, signed-out operation and legacy-store preservation.

Live production export, independent-store import, updates and cleanup are being verified separately. Schema deployment and authenticated dry runs alone are not recorded as completed production synchronization tests.
